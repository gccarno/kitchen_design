# Android (Capacitor) shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** A debug-installable Android APK that is a thin native shell around the hosted web app, with working back button, file export (share sheet), camera/photo input, and a retrying offline/cold-start page.

**Architecture:** Capacitor with `server.url` pointing at the deployed site (`CAP_SERVER_URL`), so UI changes ship on redeploy. Native bits are minimal and feature-detected so the web build is unaffected. The APK is built in GitHub Actions (this machine has no JDK); the Android SDK exists locally but Gradle is not required locally.

**Spec:** `docs/superpowers/specs/2026-10-14-mobile-cloud-design.md` (Phase 7).

## Global Constraints
- `appId: "com.homedesign.app"`, appName "Home Design". No secrets or keystores in git (`*.jks`, `*.keystore`, `keystore.properties`, `local.properties` ignored).
- Native code paths run only when `Capacitor.isNativePlatform()`; web behavior, unit tests and e2e (37/37, `LLM_API_KEY=''`) must be unchanged. `@capacitor/*` imports in app code must be dynamic (`await import(...)`) so the web bundle does not need them at runtime.
- `server.url` comes from env `CAP_SERVER_URL` (required for sync; fail loudly in `capacitor.config.ts` if unset when `CAP_REQUIRE_URL=1`); `cleartext` only when the URL starts with `http://` (LAN dev).
- Navigation is restricted to the app origin: `server.allowNavigation` = the host of `CAP_SERVER_URL`.
- Do not run `npx cap sync`/gradle steps that need a JDK locally; `npx cap add android` and file edits are fine.
- Snapshot files (`elevation-svg.test.ts.snap`, `example-layouts.test.ts.snap`) are never committed. Trailers: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, `Claude-Session: https://claude.ai/code/session_01Ci5vpeZ6daMwqsFnDbRH6w`.

## Review Focus
- A malicious or compromised link must not navigate the WebView to a foreign origin with the app's bridge exposed.
- Export download while on native must save+share the real bytes (PDF/CSV/PNG/SVG), not an HTML error/login page (check `res.ok` and content-type).
- Back button on the root route exits the app instead of trapping the user; elsewhere it goes back.
- Camera/photo input works: Android manifest has the permissions the file input with `capture` needs.
- `android/` build artifacts and local config are not committed.
