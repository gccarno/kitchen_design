# Parts list and cost estimate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A priced parts list for kitchens and closets, with editable prices saved in the project, and a CSV export.

**Architecture:** `Project.pricing` (optional) holds the overrides. It's edited through the same JSON Patch revisions as the canvas, so undo works. The pure `buildEstimate` turns a project and the catalog into lines and totals. `EstimatePanel` shows them and edits prices, and a CSV route exports them.

**Tech Stack:** Next.js 15 route handlers, React 19, Zod, Vitest with Testing Library (no jest-dom), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-11-estimate-design.md`

## Global Constraints

- All lengths are stored in mm. `units` only changes the display (m² vs ft² for the countertop).
- Default rates: `{ countertopPerM2: 350, installPct: 30, taxPct: 0, hardwareEach: 4 }`. The default currency is `'USD'`.
- Cabinet formula: base 120 + 0.25/mm, wall 90 + 0.2/mm, tall 300 + 0.5/mm, corner 350 (base) or 220 (wall), filler 25.
- Closet prices: shelf 30/m, rod 15/m, shoe_shelf 40/m, hooks 20/m, drawers 60 per drawer, tower 180, basket 25, valet_rod 20.
- Chat commands never produce `/pricing` ops.
- Copy: "Prices are rough estimates; change any of them to match your quotes."

## Review Focus

1. **Bad currency code** (for example "usd1" or "EU"): the schema rejects anything that isn't 3 letters, and the display falls back to USD instead of throwing a RangeError. The panel test types "EU" and expects no save.
2. **Wall-mounted fillers and corners must not count toward the countertop.** Only floor items count. Tested in the estimate tests.
3. **Inch projects:** the countertop is shown in ft² at the per-ft² price, and the line total doesn't change. Tested in the estimate tests.
4. **Typing the same value, or an empty field, must not save a revision.** Tested in the panel test.
5. **Undo of a price change restores the previous pricing**, including removing `pricing` entirely the first time. Tested in diff and e2e.
