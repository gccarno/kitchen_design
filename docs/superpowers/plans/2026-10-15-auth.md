# Auth (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Email/password accounts. Every project belongs to a user; web and Android clients authenticate with the same session token.

**Architecture:** Users and hashed session tokens live in Postgres. A random 32-byte token is set as an httpOnly `session` cookie (and also accepted as `Authorization: Bearer`). Next.js Node-runtime middleware redirects/401s unauthenticated requests; `getStorage()` re-validates the token itself and returns an owner-scoped `PgProjectStore`. Auth is **on only when `DATABASE_URL` is set**; the disk backend (local dev, Vitest, Playwright) stays open and single-user, exactly as today.

**Tech Stack:** Drizzle + postgres-js (existing), `node:crypto` scrypt, Next 15.5 middleware with `runtime: 'nodejs'`, Zod.

**Spec:** `docs/superpowers/specs/2026-10-14-mobile-cloud-design.md` (Phase 2). Branch from `main`: `feat/auth`.

## Global Constraints

- Auth enabled iff `process.env.DATABASE_URL` is non-empty. Disk mode: no login, no middleware effect, `getStorage()` unchanged.
- Passwords hashed with `node:crypto` scrypt (deviation from the spec's argon2: no native module to build for Render/arm64/Capacitor). Format `scrypt$<N>$<r>$<p>$<saltB64>$<hashB64>`, N=16384, r=8, p=1, 64-byte key, 16-byte salt, compared with `timingSafeEqual`. Min password length 10, max 200. Emails: trimmed, lowercased, Zod `.email()`, max 254.
- Session tokens: `randomBytes(32)` base64url; only the SHA-256 hex digest is stored (`auth_tokens.token_hash`). Cookie name `session`, httpOnly, SameSite=Lax, Secure when `NODE_ENV==='production'`, Path=/, Max-Age 31536000.
- Login/register failures never reveal whether an email exists (same message, 401 / 400 respectively; login on unknown email still runs a dummy scrypt verify).
- Registration is open only when the users table is empty or `ALLOW_REGISTRATION=1`; otherwise 403.
- Public paths: `/login`, `/api/auth/*`, `/api/health`, static assets (`_next/*`, favicon, icons, manifest). Everything else requires auth.
- State-changing auth routes (`register`, `login`, `logout`) require `Content-Type: application/json` (cheap CSRF guard on top of SameSite=Lax).
- Never log passwords or tokens. Drizzle migrations are generated with `npx drizzle-kit generate`, committed in `drizzle/`, and must pass the existing migration tests.
- Tests: Vitest on PGlite (`sharedTestDb`). `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm run e2e` (disk mode, must stay green) all pass at the end of every task. Never commit the two snapshot files `elevation-svg.test.ts.snap` / `example-layouts.test.ts.snap` if `npm test` rewrites them.
- Commit trailers: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01Ci5vpeZ6daMwqsFnDbRH6w`.

## Review Focus

1. A forged `x-user-id`/similar header or a client-supplied cookie for another user never yields another user's data (getStorage trusts only a validated token).
2. A revoked/unknown/expired token on an API route gives 401 JSON, on a page redirects to `/login`; never a 500 or a leaked project.
3. Two users: user B cannot read, update, delete, duplicate, or fetch photos of user A's project (404, not 403).
4. Login timing and messages do not reveal whether an email exists; brute force is throttled.
5. First-user registration claims the null-owner rows left by `import:local`; later users start empty.

**Interfaces:**

  - Tables: `users(id uuid pk default gen_random_uuid(), email text unique not null, password_hash text not null, created_at timestamptz not null default now())`; `auth_tokens(token_hash text pk, user_id uuid not null references users(id) on delete cascade, label text, created_at timestamptz not null default now(), last_used_at timestamptz)`.
  - In `users.ts` (all take `db: Db`): `userCount(db): Promise<number>`; `createUser(db, email, password, opts?: { claimOrphans?: boolean }): Promise<{ id: string; email: string }>` — throws `EmailTakenError` on duplicate (catch unique violation; do not pre-check only), validates email/password per Global Constraints (throws `InvalidCredentialsInputError` with a user-safe message); when `claimOrphans` is true, in the same transaction `UPDATE projects SET owner_id = <new id> WHERE owner_id IS NULL`; `authenticate(db, email, password): Promise<{ id: string; email: string } | null>` (always runs one scrypt verify, dummy hash if no such user); `createSession(db, userId, label?): Promise<string>` returns the raw token; `userForToken(db, token): Promise<{ id: string; email: string } | null>` (updates `last_used_at` at most once per hour); `revokeToken(db, token): Promise<void>`.
